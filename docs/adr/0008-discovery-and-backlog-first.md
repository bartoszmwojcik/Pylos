# 0008. Discovery and a backlog come before any spec or code

## Status

Accepted. The brief marks this decision active, with the project owner as decider.

## Context

The owner prefers to settle what to build before building it.

## Decision

We do discovery and write a backlog before any spec or code. The result is the product brief and the issues #1–#12 and #15.

## Consequences

- No code is written for a feature without a routed decision.
- Backlog issues must follow the brief ids. Issues that cite superseded rows (R01, R02, N01) need updating before work starts.
- Changing the brief needs the owner's approval.
